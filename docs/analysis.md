# Анализ legacy_calc.py

Логика алгоритма:
Функция `calc_bonus(x, y, z)` рассчитывает бонус в зависимости от суммы продаж (x), количества месяцев (y) и категории клиента (z).
- Если сумма продаж больше 1000, бонус считается в цикле по месяцам: за каждый месяц к результату добавляется доля от суммы продаж. Доля зависит от категории клиента: 15% для категории 1, 10% для категории 2, 5% для остальных.
- Если сумма продаж не больше 1000, бонус считается одной формулой: x * y * 0.02 при количестве месяцев больше 10, иначе x * y * 0.01.

Выявленные недостатки (Code Smells):
1. Магические числа: 1000, 0.15, 0.10, 0.05, 10, 0.02, 0.01. Их нужно вынести в константы.
2. Плохой нейминг: x, y, z не отражают бизнес-смысл (лучше sales_amount, months, client_category), а имя функции и результата `res` слишком общее.
3. Глубокая вложенность: цикл внутри условия внутри условия.
4. Избыточный цикл: переменная `i` не используется, а на каждой итерации прибавляется одно и то же значение. Цикл равносилен умножению x * ставка * y.
5. Дублирование логики: расчёт бонуса для разных категорий и порогов повторяется в нескольких ветках.
6. Нет проверки входных данных: отрицательные суммы и месяцы, нулевое y и неизвестная категория z (любое значение, кроме 1 и 2, молча попадает в ветку «else» со ставкой 5%).
7. Нет документации (docstring) и тестов.
8. Для денежных расчётов используется float, что даёт ошибки округления (лучше Decimal).
